# Controlled account review

The dedicated Account Review route and the same standalone stories independently exercise five exports of the existing private MIT `@hollis-labs/kit-account@0.0.0` candidate: AccountProfile, AccountPreferences, WhoamiBadge, ApiTokenManager and ConnectedAccounts. This is a reviewed development snapshot, not a registry release. `third_party/README.md` and `kit-account-provenance.json` retain source commit, unchanged runtime/source.css, original source hashes, license and archive SHA256 `3c69fd3041bb4a2d040d8b5d46ba9d5a26028388ee35030ff6d93deabc951e7f`. Existing design-components/tokens0.4.0, React19, Bundler type resolution and candidate source registration remain unchanged. No new host API, package version or upstream build.

## Data and policy

`account-review/v1` projects the unchanged `administration/v1` fictional users/roles/permission labels at fixed UTC2026-10-04T14:30:00Z. The principal selector uses those actual records, including locked USER-003. Token/provider rows and scope labels are separately authored presentation annotations with an explicit principal link, not historical access receipts or authorization results. No token value, prefix, hash, credential or provider secret exists. Profile display-name/email drafts never modify the fictional identity or its local assurance. Reviewed-copy identity changes the source lease without changing records. The route uses an unfiltered full snapshot and pauses operation playback; no family-wide reconstruction claim.

Two modes separate profile/preferences from access metadata. Native profile required-name and optional email validity remain mounted. The host also rechecks a trimmed nonempty name and the HTML email grammar (including `a@b`) before immediate admission and producer commit; it imposes no extra length cap. Invalid current drafts visibly disable Save and show feedback that clears after correction. Preferences have host-rendered controlled density/boolean fields; false is preserved. Token drafts require a nonempty name and unique current scope IDs. Unavailable scopes produce the genuine kit alert and its local clear action. Unknown status strings remain neutral rows with no connect/revoke action. Actual active/canRevoke and known provider state/capability checks are repeated by the host, never treated as permission evaluation.

Every mandatory Save/Create/Revoke/Connect/Disconnect callback only opens a labelled finite local candidate-intent inspection. No supplied principal, token/provider row, status or permission changes; no saved/created/revoked/connected outcome is reported. All upstream fixed action labels are described by an adjacent no-effects caption. The fixed revoke sentence cannot be overridden: it describes the upstream action, which this host does not execute. Policy is not passed as a fake revoke error. Confirmation closes before the local inspection opens. NewTokenDisclosure stays deferred and unmounted; no clipboard, download, persistence, OAuth, provider call or authentication evaluator.

## Supported appearances and limitations

Recorded, empty metadata, identity loading/error/unknown, denied, read-only, locked principal, long content, unknown status, invalid profile, unavailable scope, busy profile/metadata, metadata loading/error use actual controlled props and explicit host policies. Unknown/loading/error identity withholds profile, drafts and token/provider content. Metadata loading/error is separate and retains only clearly labelled fictional snapshot rows, with actions refused; this is not a refresh receipt. Busy `Saving…`/`Creating…` is selected appearance, not a running operation. AccountProfile has no independent loading prop and ConnectedAccounts has no confirm prop; identity gating and local inspection compose those boundaries rather than claiming invented APIs. No identity verification appearance is asserted by editing a profile.

## Lifetime, layout and evidence

`Review.tsx` reuses the finite app-owned admin presentation session. Every effect lifetime constructs a fresh session (including React.StrictMode replay) and disposes only its captured session. Immediate callbacks require current source/principal/state/mode/render lease and current draft/target. Captured old confirmation/close callbacks cannot admit or retire a newer target. Draft/selection/state/source/mode/reset/unmount cancel tickets and clear target/result. Held FIFO producers re-evaluate the same current candidate before synchronous ticket commit. Focus restoration is bound to current lease/source/origin and cancelled on new presentation/unmount. FIFO release can retire old outcomes; it never reports business execution.

One existing AppShell/page-scroll owns ordinary content; the local DetailDialog owns its bounded body scroll. Scoped inherited plan metadata/footer styles wrap source identities and preserve fixed UTC, raw JSON and controls on narrow screens. Public type assertions ensure actual upstream props do not silently become any. Meaningful browsers cover native/email/scope validity, current identity, immutable rows, old native confirmation and modal callbacks, held source retirement, real development StrictMode, rendered input tokens, keyboard modal containment/return, verified narrow dark bounds and API-free standalone states. Inventory claims remain bounded to these five exports and concrete supported states; imported types remain partial. Broad fixture/reference/contracts work remains partial.
