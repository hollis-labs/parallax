The reference entry is `?example=torque&profile=torque-16w`. The legacy dashboard also offers **Open Torque Activity reference**. Both use the existing standalone app shell, routes, admitted selection, review drawer and original source clock. The ordinary lab Activity view is unchanged. Mission Control and Usage remain adaptations pending CW-20261008-0050.

Native disclosures provide 112 calendar rows and 24 exact UTC pulse intervals. Zero is not a fake scale-floor peak of one. If all pulse intervals are Unknown, its total and peak are also explicitly Unknown; covered empty intervals still produce zero. Partial counts are labelled at the cutoff. The graphics are supplemented by exact accessible tables and visible total/peak values. Recent-run focus has an app-owned token outline, independent of the kit's background-only default. Selection callbacks recheck the current source/query/cutoff/resource and live presentation lifetime; old tab/unmount callbacks cannot navigate a new view. The effect-owned lifetime supports development StrictMode replay.

Shared fullscreen portable stories use the same Torque composition, source and model; no API or plugin delivery is mounted in the story host. `frontend/tests/torque-activity.spec.ts` checks actual left/right age boundaries, receipt-time prefix, discrete paint, UTC table endpoints, real keyboard recent/detail access, current callback retirement, complete desktop/narrow/short-height captures and resource/unknown/sparse portable states. Reference fidelity is bounded to this Activity presentation and its documented UTC/coverage transformations; it does not claim all shared widget props, live transports, Mission/Usage parity or comprehensive fixture-family coverage.
