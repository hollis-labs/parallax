# Review Workbench

The Workbench is an app-owned catalogue of 26 existing review destinations, not runtime plugin discovery or a new component review family. `workbench/catalog.ts` is the finite label/icon/source/scope/gap/story registry used by both the main navigation and the Workbench cards. Review Workbench is an additional prominent entry; Activity remains the default. Every declared representative story exists in the built index. Examples explicitly links a representative primitive story rather than claiming a portable copy of its entire mixed page. No public export disposition is promoted by this checkpoint.

The visible groups are Operations, Communications, Administration, Evidence, Developer and Voice. Native SearchInput, group selection and reset filter this metadata locally; counts distinguish matching destinations from 26 declared views, never task or receipt counts. Each card states its source kind and bounded review limit. Fixed snapshots, compatible eight-record prefixes and authored specimens remain distinct. Catalogue metadata remains available when operations records are empty or withheld; this does not admit the target page's records or override resource policy.

Workbench entry explicitly pauses the current playback frame. Its context caption and selected-record band use the current projected cutoff, not a silent full snapshot. Ordinary playback-to-playback navigation retains its prior behavior; nonplayback entry retains the existing pause policy. The common finite navigation path is used by native navigation, Workbench cards, Layouts and plugin local routes. Existing plugin context/invocation retirement and child unmount cleanup fence prior view producers; there is no new lifecycle engine. Local record selection is retained only while admitted in the current graph. Changing scenario retires the source and clears selection/filter state.

Known view/scenario/theme/mode/layout/navigation parameters retain their existing reload contract. Reload does not serialize the playback cursor or selected record and opens the current scenario snapshot. Unknown view requests normalize to Activity with an explicit initial fallback notice; arbitrary requested strings are never destinations or executable markup. Theme/layout/navigation behavior is not expanded into a new router.

Portable compositions mount only the Workbench and a controlled local navigation callback, not App/plugin hosts. Normal portable links derive their host from actual location.host, including the deployed Storybook hostname. Story IDs must belong to the declared catalogue. Trusted live hosts parallax.nanite.cloud, parallax.os.nanite.cloud, parallax-stories.nanite.cloud, 192.168.1.195 and 100.112.71.40 map to https://parallax-stories.nanite.cloud; app proof 18541/18545 and story proof 18542 map to local 18542, known normal localhost 18441/5173 and local story 18442 map to 18442. Unknown hosts withhold links with a visible caption. No arbitrary user-provided URL, discovery request or external data fetch is accepted. Clicking a story is ordinary declared review navigation, not retrieval of business data.

Search/group/reset/source changes advance a local currentness lease; old card callbacks cannot navigate after filtering, source replacement or unmount. Real development React.StrictMode setup refreshes the lifetime. Controlled story argument/source changes remount the metadata projection. Native keyboard typing retains search focus, Enter opens an admitted destination, and real story links open their representative API-free composition. Desktop and 390px dark layouts use the established theme tokens, one AppShell and one page-scroll; no heavy optional modules are imported by the registry.

No new independent runtime export claims, dependencies, upstream edits, business changes, copying, saving or deployment effects are introduced.
