## Upstream proposal, not promotion

After owner review and DEC026's distinct second-consumer proof, consider narrowly
extracting Approval (risk + controlled decision), Proposal field slots, Report
metric/summary slots, terminal/error card layouts, and the banner grammar into
kit-chat. PromptCard/ConfirmationCard already cover elicitation's input primitive.
Native ChatInput already covers slash/@ selection; rich editor chips/grouped
command metadata would need a demonstrated second consumer, not a Tiptap transplant.
Inline and drawer placements of Flux do not establish two consumers.

The kit's command selection queues focus restoration after onSelect. A host that
opens a modal from onSelect must give the modal a chance to own focus afterwards.
Native checks establish the actual behavior; no shared source patch is made here.
No provider/transport/polling/SSE, real retry/approval, OS IME/physical-touch proof,
kit publication/version/tag, service/config/deploy, or production Flux/Tangent
adoption is included.
